* Plan

forge's sandbox commands take =--id= (the task's =:ID:=) and its work
commands take =--book= (the name part of the Denote workbook).  When
=M-x bb-transient= is opened from a =task.org=, both should already be
filled in from where point is, and the menu should be the =:REPO:=
project's.

Example: point anywhere in
=~/work/20261024T125424--sandboxes/06510D5A-4A35-436B-91A4-A6A2D44CEA45/task.org=
should give

| Option   | Value                                  | From                        |
|----------+----------------------------------------+-----------------------------|
| =--id=   | =06510D5A-4A35-436B-91A4-A6A2D44CEA45= | =:ID:=, inherited           |
| =--book= | =sandboxes=                            | the Denote name in the path |
| project  | =~/src/github.com/atomstream/forge=    | =:REPO:=, inherited         |

The rules are written in cljbang, so they can sit in bb.edn and still
read like Clojure.

** Two problems, two homes

1. Which project :: has to be known /before/ any bb.edn is read, so it
   can't live in bb.edn.  It goes in the Emacs config, as a new
   =bb-transient-project-function=.
2. What to fill in :: depends on the commands' options, so it lives in
   the bb.edn that defines them, as =:bb-transient/defaults=.

** Checked so far

In the running Emacs, with point at the end of the example =task.org=:

bb's own reader limits what a form can say in bb.edn:

| Form in bb.edn | bb                                                                |
|----------------+-------------------------------------------------------------------|
| =(el/f ...)=   | fine                                                              |
| ='x=           | fine                                                              |
| =(fn [m] ...)= | fine                                                              |
| =#"..."=       | "Invalid regex literal found in EDN config, use re-pattern instead" |
| =#(...)=       | not cljbang either; use =fn=                                      |

=re-pattern= takes Emacs regex syntax, not Java's.

** Decisions

- Keys are option names :: one =:bb-transient/defaults= map per bb.edn
  covers every command that has that option: =sandbox up=, =land=,
  =down=, =checkout= get =--id=; =work start=, =plan=, =stop= get
  =--book=.  A command without the option ignores the key.
- Per-command overrides :: the same key in a task map or on an
  =:exec-fn='s metadata wins over the bb.edn-wide one, like
  =:bb-transient/terminal=.
- Only the owning bb.edn :: forge's defaults fill only forge's commands,
  not the =:REPO:= project's tasks shown in the same menu.
- When :: each time an options menu opens, in the buffer and at the
  point =M-x bb-transient= was called from.  =nil= or an error leaves
  the option blank; an error also shows a message.
- cljbang is optional :: without it, defaults are skipped with one
  message.
- No "around" hook :: commands run asynchronously, so "around" would
  only wrap starting the process.  =before= and =after= (below) cover it.

** Open questions (taken as proposed)

- A filled value vs. the value transient remembers from the last run:
  the filled value wins, since the menu should reflect where point is.
  Other remembered args stay.
- Trust: bb-transient already runs the project's code through bb to
  read the tasks; this also runs it inside Emacs.
  =bb-transient-eval-hooks=: =t=, =nil=, or =ask= (the default) once
  per project and session.  =ask= prompts when the top menu is built,
  not while a menu is up.

* TODO Later: =before= and =after= hooks

Per task or per =:exec-fn=, not bb.edn-wide.

- =:bb-transient/before (fn [{:keys [args dir]}] ...)= :: in the
  original buffer, just before the command starts.  Returns new args,
  =nil= to keep them, or throws to cancel the run.  E.g.
  =(el/save-some-buffers t)= before =sandbox land=.
- =:bb-transient/after (fn [{:keys [exit buffer]}] ...)= :: when the
  process exits, from a hook local to the output buffer.  E.g. reload
  =task.org= after =sandbox up= attaches it.
