* Fill options from point

forge's sandbox commands take =--id= (the task's =:ID:=) and its work
commands take =--book= (the name part of the Denote workbook).  When
=M-x bb-transient= is opened from a =task.org=, both should already be
filled in from where point is, and the menu should be the =:REPO:=
project's.

Example: point anywhere in
=~/work/20261024T125424--sandboxes/06510D5A-4A35-436B-91A4-A6A2D44CEA45/task.org=
should give

| Option   | Value                                  | From                        |
|----------+----------------------------------------+-----------------------------|
| =--id=   | =06510D5A-4A35-436B-91A4-A6A2D44CEA45= | =:ID:=, inherited           |
| =--book= | =sandboxes=                            | the Denote name in the path |
| project  | =~/src/github.com/atomstream/forge=    | =:REPO:=, inherited         |

The rules are written in cljbang, so they can sit in bb.edn and still
read like Clojure.

** Two problems, two homes

1. Which project :: has to be known /before/ any bb.edn is read, so it
   can't live in bb.edn.  It goes in the Emacs config, as a new
   =bb-transient-project-function=.
2. What to fill in :: depends on the commands' options, so it lives in
   the bb.edn that defines them, as =:bb-transient/defaults=.

** Checked so far

In the running Emacs, with point at the end of the example =task.org=:

bb's own reader limits what a form can say in bb.edn:

| Form in bb.edn | bb                                                                |
|----------------+-------------------------------------------------------------------|
| =(el/f ...)=   | fine                                                              |
| ='x=           | fine                                                              |
| =(fn [m] ...)= | fine                                                              |
| =#"..."=       | "Invalid regex literal found in EDN config, use re-pattern instead" |
| =#(...)=       | not cljbang either; use =fn=                                      |

=re-pattern= takes Emacs regex syntax, not Java's.

** Decisions

- Keys are option names :: one =:bb-transient/defaults= map per bb.edn
  covers every command that has that option: =sandbox up=, =land=,
  =down=, =checkout= get =--id=; =work start=, =plan=, =stop= get
  =--book=.  A command without the option ignores the key.
- Per-command overrides :: the same key in a task map or on an
  =:exec-fn='s metadata wins over the bb.edn-wide one, like
  =:bb-transient/terminal=.
- Only the owning bb.edn :: forge's defaults fill only forge's commands,
  not the =:REPO:= project's tasks shown in the same menu.
- When :: each time an options menu opens, in the buffer and at the
  point =M-x bb-transient= was called from.  =nil= or an error leaves
  the option blank; an error also shows a message.
- cljbang is optional :: without it, defaults are skipped with one
  message.
- No "around" hook :: commands run asynchronously, so "around" would
  only wrap starting the process.  =before= and =after= (below) cover it.

** Open questions (taken as proposed)

- A filled value vs. the value transient remembers from the last run:
  the filled value wins, since the menu should reflect where point is.
  Other remembered args stay.
- Trust: bb-transient already runs the project's code through bb to
  read the tasks; this also runs it inside Emacs.
  =bb-transient-eval-hooks=: =t=, =nil=, or =ask= (the default) once
  per project and session.  =ask= prompts when the top menu is built,
  not while a menu is up.

* =before= and =after= hooks

Use case: in =atomstream/forge=, after =bb work start= Emacs should
1. open every new =task.org= with =find-file-noselect=, so their
   =:ID:= links resolve, and
2. take the user to the new =workbook.org=.

=work start= already prints the new directory as its last line, so the
=after= hook can read it from the output.  It is a lot to write inline in
bb.edn, so the hook is a function in a cljbang file:

#+begin_src clojure
  ;; forge: src/work.clj
  (defn start
    {:org.babashka/cli {...}
     :bb-transient/before 'forge.hooks/save-book
     :bb-transient/after  'forge.hooks/open-book}
    [opts] ...)
#+end_src

#+begin_src clojure
  ;; forge: emacs/forge/hooks.clj, run by cljbang
  (ns forge.hooks
    (:require [clojure.string :as str]))

  (defn save-book
    "start refuses a workbook with unsaved changes, so save them first."
    [_]
    (el/save-some-buffers true)
    nil)

  (defn open-book [{:keys [exit out]}]
    (when (zero? exit)
      (let [dir (-> out str/trim str/split-lines last)]
        (doseq [f (el/directory-files-recursively dir "\\`task\\.org\\'")]
          (el/find-file-noselect f))
        (el/find-file (el/expand-file-name "workbook.org" dir)))))
#+end_src

** The hooks

A hook belongs to one command.  It can be set in the task map or in the
=:exec-fn='s metadata, and the task map wins, as with
=:bb-transient/terminal=.  There is no bb.edn-wide hook.

- =:bb-transient/before= :: called with ={:args [...] :dir "..."}= in
  the buffer =M-x bb-transient= was called from, just before the
  command starts.  It returns a new args vector, or =nil= to keep the
  args it was given.  If it throws, the run is cancelled and the error
  is shown as a message.
- =:bb-transient/after= :: called with ={:exit 0 :out "..." :buffer
  <output buffer> :args [...]}= when the process exits, in the original
  buffer if it is still live, otherwise in the output buffer.  Its
  return value is ignored, and if it throws the error is shown as a
  message.

=:args= are the strings bb gets: ="--book=sandboxes"=.  =:out= is the
text the process wrote (stdout and stderr together, as the buffer
shows them), without compile's header and footer.

A hook's value is one of:
- a fully qualified symbol :: =forge.hooks/open-book=.  Its namespace
  is =require=-d from the project's =:bb-transient/cljbang-paths=
  (below) before the first call.
- an =(fn ...)= form :: for one-liners, e.g.
  =(fn [_] (el/save-some-buffers true) nil)=.

Since =:exec-fn= metadata is evaluated, the value has to be quoted there.
In a task map it doesn't.

** Decisions

- Hooks are sent the same way as defaults :: =bb-transient.clj= puts
  them on the leaf as strings (=pr-str=), ="before": "forge.hooks/save-book"=,
  next to =terminal= and =defaults=.  A plain =:task= without an
  =:exec-fn= can have hooks too.
- =:bb-transient/cljbang-paths= :: a new top-level key in bb.edn, with
  directories relative to the project that are added to
  =cljbang-load-path= while a hook runs.  forge uses =["emacs"]=.  No
  default, since =src/= is bb's and isn't meant for cljbang.
- One way to watch the process exit :: =add-function :after= on the
  output process's sentinel.  This works for =compile= and
  =ghostel-compile= alike, as long as each one leaves a process in its
  buffer.  It runs after compile has written its footer.
- Where =:out= starts and ends :: =(point-max)= of the output buffer
  right after =compile= returns.  The process can't have written
  anything yet, since its filter only runs once Emacs waits for input.
  It ends just before compile's ="\nCompilation ..."= footer.  In a
  terminal buffer it is whatever text the buffer holds.
- Only menu runs :: =bb-transient-run= stays a plain runner without
  hooks.  =bb-transient--run= takes the hooks as an optional argument.
- Trust and cljbang :: the same as defaults.  A tree with hooks counts
  as having forms when the top menu asks =bb-transient-eval-hooks=.
  When a project isn't trusted, or cljbang is missing, the command runs
  without its hooks and a message says so.
- Compiled once :: through the existing =bb-transient--compile= cache.
  =g= clears it, and also forgets which hook namespaces have already
  been required.

** Open questions (taken as proposed)

- Should =after= run on failure?  Yes, with =:exit=, so a hook can
  report the failure.  The examples check =(zero? exit)=.
- =find-file= from a sentinel uses whatever window is selected when
  the process exits.  That is good enough for now.  If it isn't, the
  hook can call =el/pop-to-buffer= itself.
