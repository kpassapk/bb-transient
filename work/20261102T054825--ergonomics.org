** Silence output

In a lot of my =bb-transient= commands, I don't care about the command output, only when something fails.
In those cases, I want no output at all, unless there has been an error, or I am asked for input.

Otherwise, the current output is good.

This should be selected command-by-command, since I know which commands my prompt and where the output actually matters.

** Copy command

Can I construct a command using info at point (as it works now), and then copy it, without executing it?
The =transient-history= command seems to include values of last commands.

Maybe achievable with a hook function and a custom command, and this is a documentation task.

The use case is: in some cases, I want to drive my workflow with agents, and in the forge can only see commands that are in source code blocks. If I execute something from a transient, it's not visible to the agent.

** Other inputs

Date inputs using calendar?

Completion-at-point functions? For example, if there is a set of known inputs, then it would be amazing if <ENTER> would pop up a capf. Or if setting a switch could trigger a CAPF.

** Command ordering and grouping

Related commands (=bb work start= / =stop=, or =bb sandbox up= / =down=) should be in order and next to each other in the transient menu.

See https://github.com/kickingvegas/casual for some crafted Transient menus, with multiple columns.
