In a lot of my =bb-transient= commands, I don't care about the command output, only when something fails.
In those cases, I want no output at all, unless there has been an error, or I am asked for input.

Otherwise, the current output is good.

This should be selected command-by-command, since I know which commands my prompt and where the output actually matters.

*** Proposal

A per-command flag, set like =:bb-transient/terminal=: in the task map
or on the =:exec-fn='s metadata.

#+begin_src clojure
  snapshot {:exec-fn work/snapshot :bb-transient/quiet true}
#+end_src

- The command runs in its usual buffer, but not displayed
  (=display-buffer-no-window= around =compile=).
- Exit non-zero: the buffer pops up, as now.
- Exit 0: a message in the echo area, =bb work snapshot: done=.
- Asked for input: when the process has written a line with no newline
  and then gone quiet (~0.3 s) while still alive, it is probably a
  prompt, and the buffer pops up. A heuristic, but it covers
  =read-line= after a =print=.
- =s= ("silent") in an options menu, next to =t=, flips it for one run.
- Terminal commands ignore it: a TUI wants its window.
- After hooks still get =:out=.

=:bb-transient/silent true= is set in the task map or on the fn's
metadata. =s= in an options menu flips it for one run, and bare leaves
can't be flipped. A silent command runs =compile= with
=display-buffer-no-window= and keeps the old =next-error-last-buffer=.
On exit 0 it shows a message. On any other exit the buffer pops up and
becomes =next-error='s buffer. When a partial line stands for 0.3 s
while the command still runs, the buffer pops up too. That happens
before the after hook runs, so the hook's own output wins. Terminal
runs ignore the flag. You didn't answer the =bb-transient-run= question,
so I went with my preference: it takes a =silent= argument. The README
has a "Silent commands" section that says the prompt check is a guess.

New tests: the tree flag, the menu's default value, =++silent= dropped
from the args, and a success, a failure and a prompt run against a new
fixture task =silent= (=ok=, =fail=, =ask=).

Run here: the introspection against the fixture with =bb=, which gives
the right =silent= flags, and a paren-balance check.
*Not run: =bb ci=.* There is no Emacs in the sandbox, so neither the
byte-compile nor the ERT suite has run. Please run =bb ci= after
landing. Two things are untested: that =compilation-start= passes
=allow-no-window= on your Emacs (if it doesn't, the buffer just shows
as before), and that windows behave in batch the way the
failure and prompt tests expect.

*** Record demo

Record the screen with OBS from the command line, then upload the file
to YouTube. OBS has no command to stop a recording, so these blocks
control the running OBS through its built-in websocket (OBS 28 and
later), using [[https://github.com/grigio/obs-cmd][obs-cmd]]. The upload uses
[[https://github.com/porjo/youtubeuploader][youtubeuploader]], which needs a
=client_secrets.json= from a Google Cloud project with the YouTube Data
API enabled. Its first run opens a browser for you to log in, and it
keeps the token in =request.token=.

Settings. If you keep its authentication on, export

** Proposal: interceptors

The copied line comes out of a data pipeline that the
layers take part in, and that pipeline runs in bb, not in Emacs.

*** The request

Picking a command in the menu, to run or to copy, gives a map. It is
the whole of what the menu decided, and the only thing that crosses
from Emacs to the layers:

| Key        | Example                                       | Set by                     |
|------------+-----------------------------------------------+----------------------------|
| =:mode=    | =:copy= or =:run=                             | the menu (=_=, copy mode)  |
| =:path=    | =["sandbox" "up"]=                            | the menu                   |
| =:args=    | =["--id" "X"]=                                | the options menu, defaults |
| =:root=    | =".../atomstream/forge/"=                     | the layer the task is from |
| =:dir=     | =".../kpassapk/bb-transient/"=                | where the command runs     |
| =:layers=  | =[{:name "atomstream/forge" :root "..."} …]=  | outermost first            |
| =:origin=  | ={:file ".../task.org" :directory "..."}=     | the buffer the menu was opened from |
| =:task=    | ={:name "up" :options [...] :silent true}=    | the leaf, as introspection read it |
| =:terminal= | =false=                                      | the task, and =t= in the options menu |
| =:silent=  | =true=                                        | the task, and =s= in the options menu |
| =:line=    | =["bb" "--config" ".../bb.edn" "sandbox" …]=  | bb-transient, see below    |

=:line= is a vector of words. Emacs quotes and joins it
(=bb-transient--quote=) only at the very end, to copy it or to hand it
to the shell, so no interceptor deals with shell quoting.

=:task= is the leaf from the cached task tree: its options, their
defaults, its flags. An interceptor that needs a task's spec reads it
there instead of resolving the =:exec-fn= again.

What Emacs reads back from the final request: =:mode=, =:line=,
=:dir=, =:terminal= and =:silent=. The rest is for the interceptors.
=:mode= may go from =:run= to =:copy=, never back: a layer can say a
command is to be pasted into a block rather than run from Emacs, but
a copy never runs anything. =:terminal= and =:silent= matter only on a
run.

*** Interceptors

A layer lists its interceptors at the top level of its =bb.edn=:

#+begin_src clojure
;; forge's bb.edn
{:paths ["src"]
 :bb-transient/interceptors [atomforge.transient/aa]
 ...}
#+end_src

Each is a qualified symbol naming a var in that layer's classpath
(=:paths=, =:deps=), holding an interceptor:

#+begin_src clojure
;; forge: src/atomforge/transient.clj
(ns atomforge.transient)

(def aa
  "Copy a command as aa, which runs it from any layer of the chain.
  Runs still use bb --config: Emacs may not have aa on its PATH."
  {:name  ::aa
   :leave (fn [{:keys [mode path args] :as req}]
            (cond-> req
              (= mode :copy) (assoc :line (into ["aa"] (concat path args)))))})
#+end_src

=:enter= and =:leave= are each a function of the request that returns
the request: map in, map out. Either may be left out; a bare function
in place of the map is its =:leave=. They are pure: no output, no
files written, no processes. They may read files (=:origin= is there so
they can find a =.stub=, say).

*** The chain

Pedestal's order, with the layers as the queue, outermost first, and
bb-transient's own step at the end:

1. Every =:enter=, outermost layer first. Here an interceptor changes
   what runs: =:path=, =:args=, =:dir=.
2. bb-transient builds =:line= from the final =:dir=, =:root=, =:path=
   and =:args=: =bb --config <root>/bb.edn …= when =:dir= is not
   =:root=, =bb …= when it is. This is =bb-transient--line=, moved to
   Clojure.
3. Every =:leave=, innermost layer first. Here an interceptor changes
   how it is written: =:line=.

Splitting it this way is what lets an =:enter= move =:dir= without
having to rebuild the line, and a =:leave= rewrite the line knowing
=:dir= is final. The outermost layer has the last word on =:line=,
which suits =aa=: forge's chain is what =aa= runs, so forge says how a
line for it is written. An inner layer that wants its own line sets a
key in =:enter= that forge's =:leave= respects, or its project leaves
forge's chain.

| Without interceptors                                   | With forge's =aa=      |
|--------------------------------------------------------+------------------------|
| =bb --config ~/src/.../forge/bb.edn sandbox up --id X= | =aa sandbox up --id X= |
| =bb test=                                              | =aa test=              |

A project whose chain doesn't reach forge gets no =aa=, since no layer
of it lists one.

*** Uses

Things a layer can do with the chain:

- /Modify how the line is written/ (=:leave=)
  - Wrap a run in the layer's toolchain: =direnv exec . bb …=,
    =nix develop -c …=, =mise exec -- …=. Emacs's PATH often lacks
    what the layer needs.
  - Run inside a box: prefix =podman exec box-… =, and set =:terminal=.
  - Make a copy portable: =~/src/…= for =/home/…/src/…=, or
    =cd ~/src/… &&= first, so a pasted line runs from anywhere.
  - Environment: =FOO=bar aa …=, as words.
- /What runs/ (=:enter=)
  - Shorter copies: drop args equal to their defaults in =:task=.
  - Normalize args: paths against =:dir=, canonical ids.
  - Rename: an old =:path= to its new name while a task migrates.
  - Use a dev checkout: point =:root= at a local worktree of a layer.
  - Pick =:dir=: the git toplevel, a monorepo subproject, a worktree,
    from =:origin= and the filesystem.
  - Fill an option the filesystem knows when it is missing, as forge's
    =:book= (a regex on the file name) and =:root= (the =.git= above
    it) defaults do now.
- /Guards/
  - Refuse a run by throwing: =sandbox land= on a dirty checkout, or a
    combination of options a =babashka.cli= spec can't express. A copy
    still gets the default line.
  - Turn a run into a copy, for commands the operator runs from a block.

What it does not cover:
- /Defaults in the menu./ The chain runs after the pick, not when the
  menu opens. A value an =:enter= fills is not shown or editable in
  the menu, and "(required)" is checked before the chain, so it is not
  satisfied by one. That stays =:bb-transient/defaults=.
- /Effects./ No log, no files, nothing after the run. That stays the
  before and after hooks.

*** Where it runs: bb, not Emacs

Emacs makes one call, =bb -f bb-transient.clj intercept=, with the
request as JSON on stdin, and reads the final request back. The
threading through the layers, the =:line= step, and the defaults for
missing keys are all in =bb-transient.clj=. Each layer's interceptors
run on that layer's classpath: the script runs them with =bb --config
<layer>/bb.edn= for each layer that lists any (one, forge, in
practice), passing the map along.

Compared with the cljbang hook:
- *No trust prompt, no cljbang.* bb already loads a layer's code to
  read its tasks, and runs it when a task runs. An interceptor is that
  same code, run the same way.
- *Testable without Emacs.* An interceptor is a function of a map,
  tested with =bb test= in the layer that defines it.
- *Same from the terminal.* =atomforge= (and =aa=) can run the same
  chain to print a line, so Emacs and the CLI agree on what a command
  looks like.

The cost is a bb process per command for a menu whose layers list
interceptors. Introspection reports each layer's =interceptors=, next
to =cljbang-paths=, so a menu with none starts no process and stays as
fast as today.

*** Run and copy go through the same chain

The request carries =:mode=, and both go through the chain; Emacs then
copies =:line= or runs it in =:dir=. That makes "only a copy says
=aa=" forge's decision, in =aa='s =:leave=, instead of a rule in
bb-transient. =bb-transient-command-line= returns the =:run= line, as
now.

The before hook still runs first on a run, in Emacs, and its new args
go into the request; the after hook still runs after. Hooks stay for
effects inside Emacs (saving buffers, visiting files); interceptors
are for data. A copy calls no before hook, as now.

*** When it fails

An interceptor that throws, or a bb that exits non-zero:
- copy: the line from step 2 without the layers, with a message saying
  why. A copy never fails because of a layer.
- run: nothing runs, and the message names the interceptor, as when a
  before hook throws. Running a fallback command in a directory the
  layer meant to change would be worse than not running.

*** Layers out of Elisp

=atomforge.el= for the menu, and =chain= in =atomforge/cli.clj= for
=aa=. Both read =:forge/parent=, the elisp one with a regexp.

=bb-transient-layers-functions= gives way to a command:

- =bb-transient-layers-command=: a program and its arguments, run in

- atomforge sets it to =("atomforge" "layers" "--json")=, a new

- *The =work= directory rule.* =atomforge-directory= runs =work …= in
